# Отчёт по практическим заданиям 19–23

## Практическое задание 19: PostgreSQL и REST API пользователей

Реализовано серверное приложение на Node.js (Express) с подключением к реляционной СУБД PostgreSQL через драйвер `pg`. Данные о пользователях хранятся в таблице `users`; все маршруты работают с базой данных.

### Реализовано

- Подключение к PostgreSQL через переменные окружения
- Автоматическое создание таблицы `users` при старте с полями: `id`, `first_name`, `last_name`, `age`, `created_at`, `updated_at`.
- REST API: `POST /api/users`, `GET /api/users`, `GET /api/users/:id`, `PATCH /api/users/:id`, `DELETE /api/users/:id` с валидацией входных данных и кодами ответов при ошибках.

## Практическое задание 20: MongoDB и REST API пользователей

Реализовано серверное приложение на Node.js с подключением к MongoDB через Mongoose.

### Реализовано

- Подключение к MongoDB через переменные окружения.
- Модель пользователя с полями сериализуется в JSON.
- Полный CRUD по тем же маршрутам `/api/users`, что и в задании 19, с логикой на стороне MongoDB.

## Практическое задание 21: кэширование с Redis

Доработано приложение с RBAC (практическое занятие №11): для выборок пользователей и товаров добавлен слой кэширования в Redis.

### Реализовано

- Клиент Redis (`redis` пакет), подключение по `REDIS_URL`.
- Middleware чтения из кэша и сохранение ответа после обращения к базе данных.
- Инвалидация кэша при изменении пользователей и товаров.

## Практическое задание 22: балансировка нагрузки (Nginx и HAProxy)

Подготовлена тестовая система с несколькими экземплярами backend и двумя вариантами балансировщика.

### Реализовано

- Не менее двух рабочих backend на Node.js (Express): ответ `GET /` с указанием экземпляра (`instance`) и порта; эндпоинт `GET /health` для проверок.
- Третий экземпляр в роли резервного (`INSTANCE_ID=backup`) для сценариев `backup` в Nginx и HAProxy.
- Nginx с распределением нагрузки, резервным сервером, параметрами отказоустойчивости `max_fails` и `fail_timeout`, проксирование заголовков.
- HAProxy: frontend/backend, алгоритм `roundrobin`, HTTP health-check на `/health`, резервный сервер.
- Описание контейнеров через docker compose.

## Практическое задание 23: контейнеризация и Docker Compose

Задание выполнено как продолжение практики по балансировке: все компоненты подняты в контейнерах, без ручного запуска процессов на портах хоста.

### Реализовано

- `Dockerfile` для backend
- `docker-compose.yml`: сеть для взаимодействия сервисов
- Конфигурации `nginx.conf` и `haproxy`
